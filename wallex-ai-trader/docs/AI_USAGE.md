# استفادهٔ واقعی از AI — نقش‌ها، پرامپت‌ها، اعتبارسنجی، لاگ

سوال داوری: «آیا AI واقعاً در تصمیم استفاده شده یا تزئینی است؟»
پاسخ در این پروژه: AI **سه نقش با اثر مستقیم و قابل‌ممیزی** دارد و خروجی هر فراخوانی ذخیره می‌شود.
هیچ‌جا AI سفارش نمی‌سازد و هیچ پارامتر ریسکی را عددی تغییر نمی‌دهد.

## ۱) سه نقش

### الف) دروازهٔ ورود (`AIAgent.decide`)

برای هر سیگنالی که از آستانه رد شده، قبل از ارسال سفارش فراخوانی می‌شود:

| ورودی (JSON) | توضیح |
|---|---|
| `signal` | نماد، نوع (dip/breakout)، امتیاز، ATR%، قیمت و دلایل متنی |
| `features` | `rsi`, `bb_pos`, `trend_gap`, `vol_ratio`, `ret_1h/4h` |
| `context` | اسپرد، تغییر ۱۳ کندل اخیر، پوزیشن‌های باز، ۵ معاملهٔ آخر، درس‌های learner، drawdown |
| `wallex_mcp` | اختیاری: snapshot ابزار MCP والکس در صورت فعال بودن |

خروجی اجباری:

```json
{"approve": true, "confidence": 0.78, "size_mult": 0.9, "reason": "..."}
```

قواعد سخت (`validate_decision`):

- `approve` باید boolean باشد.
- `confidence` عدد در `[0,1]` و برای تأیید `>= min_ai_conf` (۰٫۶۰).
- `size_mult` عدد در `[0.5, 1.0]`؛ فقط می‌تواند اندازه را **کوچک‌تر** کند (AI اجازهٔ بزرگ‌کردن ریسک ندارد).
- `reason` رشتهٔ غیرخالی (حداکثر ۳۰۰ کاراکتر) و در `decisions.jsonl` ذخیره می‌شود.
- پاسخ نامعتبر / خطا / timeout / JSON ناقص → **رد** (fail-closed). هیچ ورودی به‌خاطر «AI خراب بود» انجام نمی‌شود.

### ب) ناظر ریسک (`AIAgent.review`)

حداکثر هر ۳ ساعت، ورودی: equity، اوج، snapshot بازار، پوزیشن‌ها، معاملات اخیر، حالت فعلی.
خروجی: `{"risk_mode": "normal|defensive|pause", "note": "..."}`.

- `defensive` = نصف‌کردن اندازهٔ پوزیشن‌های جدید.
- `pause` = توقف ورودهای جدید؛ **حداقل ۶۰ دقیقه** قابل برگشت نیست (`pause_min_minutes`).
- خطا/JSON نامعتبر = **حالت فعلی حفظ می‌شود** (حتی pause به normal برنمی‌گردد).
- AI نمی‌تواند استاپ/تارگت/سقف پوزیشن را تغییر دهد؛ فقط همین سه حالت.

### ج) تحلیل‌گر پس از معامله (`AIAgent.reflect`)

هر ۴ معاملهٔ بسته‌شده، آمار learner (تگ اشتباه‌ها، میانگین‌ها، تغییرات) را می‌بیند و یک «درس» متنی
(حداکثر ۴۰۰ کاراکتر، confidence در [0,1]) می‌نویسد. درس در state ذخیره و در پرامپت دروازهٔ بعدی
استفاده می‌شود. این تنها کانال اثر AI بر رفتار آینده است و متنی/قابل‌ممیزی است، نه عددی.

## ۲) Providerها و مدل

| متغیر | مقدار پیش‌فرض | توضیح |
|---|---|---|
| `WTB_AI_PROVIDER` | `anthropic` | `anthropic` یا `openai` (سازگار با OpenAI) |
| `WTB_AI_MODEL` | `claude-sonnet-5-5` | مدل فعلی Anthropic (سپتامبر ۲۰۲۶) |
| `WTB_AI_BASE_URL` | خالی | برای OpenRouter/AvalAI/Ollama/… |
| `WTB_AI_TIMEOUT_S` | ۲۵ | سقف انتظار |
| `WTB_AI_RETRIES` | ۱ | تلاش دوباره فقط برای خطای گذرا |
| `WTB_AI_CACHE_S` | ۹۰ | cache برای سیگنال یکسان (کاهش هزینه) |
| `WTB_AI_REQUIRED_LIVE` | true | live بدون AI مسدود |
| `WTB_MIN_AI_CONF` | 0.60 | حداقل اطمینان برای تأیید |

نمونه برای سرویس واسط سازگار با OpenAI (رایج برای دسترسی از ایران):

```bash
WTB_AI_PROVIDER=openai
WTB_AI_BASE_URL=https://openrouter.ai/api/v1
WTB_AI_API_KEY=sk-or-...
WTB_AI_MODEL=anthropic/claude-sonnet-5-5
```

`python -m wallexbot ui` → تب تنظیمات → «آزمون AI» یک درخواست واقعی می‌فرستد و خطا/مدل را نشان می‌دهد.

## ۳) قالب پرامپت (خلاصه)

**System** (دروازه): «تو دروازهٔ ریسک یک ربات اسپات هستی. فقط JSON بده. اگر شواهد کافی نیست رد کن.
کارمزد رفت‌وبرگشت ۰٫۷٪ است؛ معامله‌ای که سود مورد انتظارش هزینه را پوشش نمی‌دهد تأیید نکن.»

**User**: JSON شامل `signal`, `features`, `context` و در صورت وجود `lessons` و `wallex_mcp`.

**System** (ناظر): «فقط یکی از normal/defensive/pause را با دلیل کوتاه برگردان.»
**System** (تحلیل‌گر): «یک درس کوتاه و عملی از این آمار بنویس؛ عدد پارامتر پیشنهاد نده.»

متن کامل با نام‌های `SYS_GATE`، `SYS_REVIEW` و `SYS_REFLECT` در `wallexbot/ai_agent.py` است.

## ۴) لاگ و ممیزی

| فایل | محتوا |
|---|---|
| `logs/ai_calls.jsonl` | هر فراخوانی: زمان، نقش، provider، مدل، مدت، هش پرامپت، طول پاسخ و خطا — **بدون کلید و بدون متن کامل پرامپت** |
| `logs/decisions.jsonl` | `action=DECISION` با کل خروجی AI (`approve`, `confidence`, `size_mult`, `reason`) |
| `logs/decisions.jsonl` | `action=AI_REVIEW` / `AI_REFLECTION` / `AI_FAILED` / `AI_REVIEW_FAILED` |
| `logs/decisions.jsonl` | `action=LEARN` برای تغییر پارامترهای learner (مستقل از AI) |

پنل: تب «ابزارها» → «لاگ فراخوانی AI» و تب «داشبورد» → تغذیهٔ تصمیم‌ها.

## ۵) هزینه و بهینه‌سازی

- فقط سیگنال‌های عبورکرده از آستانه به AI می‌روند (نه هر کندل) → چند فراخوانی در روز.
- cache ۹۰ثانیه‌ای برای سیگنال یکسان.
- `max_tokens=400`, `temperature=0`.
- در بک‌تست، `--ai-gate` اختیاری است و `max_ai_calls=80` سقف دارد؛ بک‌تست پیش‌فرض rules-only است تا
  هزینه و نویز مدل وارد عدد عملکرد نشود.
- در `status` پنل، `ai.enabled`, provider/model و `last_error` دیده می‌شود.

## ۶) چه چیزی AI **نمی‌کند**

- سفارش نمی‌سازد، قیمت/حجم تعیین نمی‌کند، به API خصوصی والکس دسترسی ندارد.
- استاپ/تارگت/سقف ریسک را تغییر نمی‌دهد.
- در نبود کلید، سیستم متوقف نمی‌شود؛ rules-only با آستانهٔ ۵۵ ادامه می‌دهد (در live فقط با
  `WTB_AI_REQUIRED_LIVE=false`).
