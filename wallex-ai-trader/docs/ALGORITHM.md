# الگوریتم معاملاتی — قوانین دقیق و قابل‌آزمون

هدف این سند «قابل بازتولید کردن هر تصمیم» است: هر ورود/خروج باید با اعداد همین سند توضیح داده شود.
همهٔ اندیکاتورها روی کندل‌های **بسته‌شده** محاسبه می‌شوند (`closed_only` در `bot.py`، و در بک‌تست فقط
پیشوند داده تا کندل i).

## ۱) ورودی‌ها

| داده | منبع | نکته |
|---|---|---|
| کندل ۱۵دقیقه | `/v1/udf/history` با resolution=1 و تجمیع سمت کلاینت | فقط کندل کامل؛ manifest + اعتبارسنجی شکاف/تکرار |
| دفتر سفارش | `/v1/depth?symbol=` | اسپرد > ۰٫۴٪ = رد معامله |
| فهرست بازارها | `/v1/markets` | نمادهای تأییدنشده هرگز معامله نمی‌شوند (fail-closed) |
| موجودی/کارمزد | `/v1/account/balances`، `/v1/account/fee` | در live کارمزد واقعی جایگزین می‌شود |

`candle_count=220` کندل، حداقل ۱۲۰ کندل برای گرم‌شدن اندیکاتورها لازم است. اگر دادهٔ کمتری برسد،
`features()` مقدار `None` می‌دهد و هیچ سیگنالی ساخته نمی‌شود.

## ۲) ویژگی‌ها (`strategy.features`)

```text
rsi        = RSI(14) روی close ها (Wilder)
atr_pct    = ATR(14) / last_close            # کسری، نه درصد
bb_pos     = (price − lower) / (upper − lower)  # Bollinger 20، 2σ
trend_gap  = price / EMA96 − 1
ret_1h     = price / close[t−4]  − 1
ret_4h     = price / close[t−16] − 1
vol_ratio  = volume_last / SMA(volume, 20)[-2]
breakout   = price > max(high[-21:-1])
green      = close[-1] > close[-2]
```

## ۳) فیلتر هزینه (مهم‌ترین فیلتر)

```text
atr_pct >= min_atr_pct           # پیش‌فرض 0.0025 = 0.25٪
```

چرا؟ کارمزد رفت‌وبرگشت ۰٫۷٪ است. اگر نوسان ۱۵دقیقه‌ای ۰٫۲۵٪ باشد، تارگت ۶٪ (۲۴×ATR) دست‌کم چند
برابر هزینه است؛ اگر نوسان ۰٫۰۵٪ باشد، حتی یک حرکت کامل ATR هم هزینه را پوشش نمی‌دهد.
در دادهٔ نمونه ATR% بین ۰٫۲۰٪ و ۰٫۳۷٪ بود؛ عدد ۰٫۲۵٪ عمداً «کم‌معامله» است.

> این فیلتر قابل تنظیم است. پایین‌آوردن آن تعداد معامله را بالا می‌برد، اما انتظار سود را نه —
> سود خالص هر معامله = حرکت قیمت − ۰٫۷٪ کارمزد − لغزش.

## ۴) الگوی dip (بازگشت از حمایت)

همهٔ شرط‌ها هم‌زمان:

| شرط | مقدار پیش‌فرض |
|---|---|
| `rsi <= rsi_buy` | ۴۵ |
| `bb_pos <= bb_max_pos` | ۰٫۳۰ |
| `green` | کندل بسته‌شدهٔ سبز |
| `trend_gap > −max_trend_dev` | > −۴٪ (نه در سقوط آزاد) |
| `ret_4h > −0.06` | > −۶٪ |
| `atr_pct >= min_atr_pct` | ≥ ۰٫۲۵٪ |

امتیاز:

```text
score = 50 + (rsi_buy − rsi) × 1.5 + min(vol_ratio, 3) × 4 + (10 if trend_gap > 0 else 0)
score = min(score, 100)
```

## ۵) الگوی breakout (شکست با حجم)

| شرط | مقدار |
|---|---|
| `breakout` | close بالای سقف ۲۰ کندل قبل |
| `vol_ratio >= 1.8` | حجم حداقل ۱٫۸ برابر میانگین |
| `trend_gap > 0` | بالای EMA96 |
| `55 <= rsi <= 72` | مومنتوم بدون اشباع خرید |

```text
score = 50 + min(vol_ratio, 4) × 6 + (rsi − 55) × 0.5
```

اگر هر دو الگو هم‌زمان برقرار باشند، `dip` اولویت دارد (ترتیب `if/elif` در `evaluate`).

## ۶) آستانهٔ ورود و نقش AI

- مسیر **rules-only** (بدون کلید AI): `score >= max(rules_min_score, min_score)` = ۵۵.
- مسیر **AI**: سیگنال باید از `min_score` (۵۵) بگذرد، سپس دروازهٔ AI با JSON معتبر approve کند.
  `confidence < 0.60`، JSON نامعتبر، خطای شبکه یا timeout = **رد** (fail-closed).
- `learner` می‌تواند `score_bias` را +۵ کند یا نماد/نوع را موقتاً غیرفعال کند (بخش ۹).
- در هر کندل حداکثر به تعداد ظرفیت خالی (`max_positions − len(positions)`) سیگنال، به ترتیب امتیاز، وارد می‌شوند.

## ۷) اندازهٔ پوزیشن (`risk.size`)

```text
by_risk = equity × risk_per_trade / stop_pct        # زیان در حد استاپ ≈ 0.8٪ سرمایه
cap     = equity × max_pos_frac                     # هر پوزیشن ≤ 25٪
avail   = (cash − equity × reserve_frac) / (1 + fee_rate)   # نقد رزرو + کارمزد
notional = min(by_risk, cap, avail) × size_mult(AI) × bt_size_mult(بک‌تست)
```

اگر `notional < max(min_notional داخلی=120k, minNotional صرافی) × 1.02` باشد، ورود انجام نمی‌شود.

## ۸) خروج

| خروج | فرمول |
|---|---|
| استاپ اولیه | `sl = clamp(sl_atr × atr_pct, sl_min, sl_max)` = clamp(2.5×ATR, ۳٪, ۶٪) |
| تارگت | `tp = max(tp_atr × atr_pct, tp_min, 4×fee_rate)` = max(5×ATR, ۶٪) |
| تریلینگ | بعد از رسیدن به `entry × (1 + 4٪)`، استاپ = `high × (1 − 2.5٪)` |
| خروج زمانی | ۴۸ ساعت |
| تسویهٔ پایان چالش | ۴۵ دقیقه قبل از `challenge_end` (و توقف ورود از ۴ ساعت قبل) |
| Kill-Switch | افت ۵٪ از اوج → تسویهٔ کامل + توقف ورود |

**ترتیب درون‌کندلی محافظه‌کارانه:** ابتدا low با استاپِ قبل از این کندل سنجیده می‌شود، بعد تریلینگ
به‌روز می‌شود، بعد تارگت. اگر کندلی هم استاپ و هم تارگت را لمس کند، استاپ ثبت می‌شود. این کار
بک‌تست را بدبینانه می‌کند و از گزارش خوش‌بینانه جلوگیری می‌کند.

## ۹) یادگیری کران‌دار (`learner.py`)

هر معاملهٔ بسته‌شده با MAE/MFE و برچسب ثبت می‌شود:

`win | gave_back | fast_stop | never_worked | fee_drag | stale | other_loss`

- هر ۴ معامله (حداقل ۸ معامله در حافظه)، اگر ≥۴۰٪ ضررها یک برچسب داشته باشند، **یک** پارامتر یک گام
  تغییر می‌کند: `tp_atr ±0.1`، `sl_atr ±0.1`، `rsi_buy ±1`، `max_trend_dev ±0.005`، `min_atr_pct ±0.0005`.
- کران‌ها **نسبت به مقدار پایهٔ Config** تعریف می‌شوند (`bounds_for`)، نه اعداد ثابت قدیمی؛ مثلاً
  `tp_atr ∈ [0.6×پایه, 1.2×پایه]`.
- بعد از تغییر، عملکرد ۸ معاملهٔ بعدی با baseline مقایسه می‌شود؛ اگر بهتر از −۰٫۳٪ نبود، **rollback** و
  پارامتر ۲۰ معامله فریز می‌شود.
- سه ضرر پیاپی یک نماد/نوع → غیرفعال‌سازی ۱۲ ساعته؛ میانگین شرینک‌شدهٔ منفی → آستانهٔ آن نوع +۵.
- همه‌چیز با شواهد در `logs/decisions.jsonl` با `action=LEARN` ثبت می‌شود. **AI عدد را تغییر نمی‌دهد.**

## ۱۰) قیف تشخیصی

`backtest` برای هر کندل-نماد این شمارنده‌ها را ذخیره می‌کند:

- `rejected:atr_below_min_atr_pct`
- `dip_cond_failed:<شرط>` و `dip_nearmiss(only ...)`
- `signal:dip|breakout`، `passed_score:*`، `rejected:score<...>`
- `entry_skipped:*`، `entries_executed`، `pending_entries_queued`

این قیف پاسخ «چرا معامله نشد؟» را بدون حدس‌وگمان می‌دهد (`docs/ZERO_TRADES_REPORT.md`).
