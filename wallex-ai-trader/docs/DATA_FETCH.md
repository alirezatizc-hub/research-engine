# دریافت داده (fetch) — ۱ دقیقه‌ای ← ۱۵ دقیقه‌ای

**مشکل واقعی:** `GET /v1/udf/history?resolution=15` کندل‌هایی با فاصله ۶۰ ثانیه برمی‌گرداند؛ اعتبارسنجی (`candles: resolution mismatch, spacing=60s expected=900s`) درست آن را رد می‌کرد.
مستندات رسمی (api-docs.wallex.ir) فهرست resolutionهای مجاز و سقف طول بازه را ذکر نمی‌کنند؛ فقط مثال `60` دارند.

**راه‌حل:** فقط `resolution=1` درخواست می‌شود؛ تجمیع در `wallexbot/aggregate.py`:
open = اولین دقیقه، close = آخرین دقیقه، high = max، low = min، volume = مجموع؛ مرز باکت = `t - t % 900` (UTC epoch).

- درخواست‌ها ۴۸۰ دقیقه‌ای (≤۴۸۰ کندل) و با ۰٫۳ ثانیه وقفه؛ ۳۰ روز = ۹۰ درخواست برای هر نماد.
- بازه همیشه به آخرین مرز ۱۵ دقیقه‌ای *بسته‌شده* ختم می‌شود؛ کندل در حال تشکیل هرگز دریافت/ذخیره نمی‌شود.
- کندل ۱۵ دقیقه‌ای فقط با ۱۵ دقیقه‌ی کامل ساخته می‌شود. دقیقه‌ی گم‌شده، تکراری، نامرتب، timestamp میلی‌ثانیه‌ای،
  پاسخ نامعتبر یا فاصله‌ی غیر ۶۰ثانیه ⇒ **خطا و توقف** (هیچ CSV/manifest نوشته نمی‌شود)؛ هیچ مقداری پر/درون‌یابی نمی‌شود.
- `load_real_dataset` هنگام backtest دوباره سری را (شکاف/تکرار/ترتیب/هم‌ترازی) اعتبارسنجی می‌کند.
- `Wallex.candles()` (مسیر bot) هم همین مسیر را می‌رود و فقط کندل‌های بسته‌شده برمی‌گرداند.

manifest: `source`, `source_resolution_min=1`, `resolution=15`, `aggregated_client_side`, `fetched_at(_iso)`,
و برای هر نماد: `candles`, `minute_candles`, `requests`, `first_t`, `last_t`.

اگر نمادی کم‌نقدشونده باشد و در برخی دقیقه‌ها معامله‌ای نباشد، API ممکن است آن دقیقه‌ها را برنگرداند؛ در این حالت fetch
عمداً شکست می‌خورد و دقیقه‌های گم‌شده را گزارش می‌کند (تصمیم دربارهٔ حذف نماد یا پذیرش شکاف با شماست، نه به‌صورت بی‌صدا).
